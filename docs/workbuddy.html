1它是什么

JG报销助理 是一个内置于 WorkBuddy 的 AI 报销专家。它会读取 GitHub 中的公司报销规则，处理金额口径、补贴计算、差旅天数和 A4 拼贴。把电子发票放进一个文件夹，告诉它材料位置，就能生成：

产出物说明
05-需确认-报销摘要.xlsx报销摘要（阶段一），黄色标记需要你人工核对/修改的地方
09-终稿-OA差旅报销明细.xlsxOA 系统差旅报销明细（行程表 + 费用表）
09-终稿-交通费明细.xlsx交通费明细（高铁、打车逐笔）
09-终稿-A4发票-*.pdfA4 发票拼贴 PDF，可直接打印粘贴报销单
💡 支持票据类型：高铁电子客票、打车行程单（高德等）、酒店住宿专票、增值税电子发票、水单附件等。

版本机制：skill 自动跟随 GitHub 最新版

本专家不内置报销规则副本，每次开始处理报销时，会自动从公司 GitHub 仓库拉取最新版报销规则并执行。因此：

  • 报销规则升级后，你无需重新安装专家——下次使用时自动用上最新版
  • 需要你的电脑能访问 GitHub（安装 git 且网络可达）
  • 若拉取失败，专家会提示「无法连接 GitHub」，请检查网络后重试
✅ 验证记录（2026-08-17）：本专家已用最新报销规则完整跑通一单真实差旅报销（高铁 + 打车 + 住宿专票 + 补贴），金额口径、行程、A4 排版均验证正确。同事拿到本手册即可直接使用。

2安装（首次使用）

拿到安装包 jg-reimburse-assistant.zip 后，任选一种方式：

方式一：专家中心导入（推荐）

1
打开 WorkBuddy启动桌面端，等待首页加载完成
2
进入专家中心点击左侧边栏的「专家」入口
3
导入专家包在专家中心找到「导入 / 导入专家包」按钮（一般在右上角或「我的专家」页内），选择 jg-reimburse-assistant.zip
4
确认导入导入完成后，在「我的专家」列表中应能看到「JG报销助理」

方式二：手动放置（备用）

如果界面上找不到导入入口（不同版本入口位置可能不同），可用手动方式：

1
解压 zip把 zip 解压，得到 jg-reimburse-assistant/ 文件夹
2
复制到专家目录将整个文件夹复制到：
~/.workbuddy/plugins/marketplaces/my-experts/plugins/
（macOS：访达 → 前往 → 个人 → .workbuddy → plugins → marketplaces → my-experts → plugins）
3
重启 WorkBuddy完全退出后重新打开，进入「专家 → 我的专家」即可看到
⚠️ 安装后如未立即显示，请完全退出并重启 WorkBuddy 一次（不是关窗口，是退出应用）。

3使用流程

3.1 准备素材文件夹

把本次要报销的全部票据（.pdf / .xml / .ofd，压缩包 .zip 也行）放进一个文件夹，例如 ~/Desktop/报销/8月差旅/。

💡 一个文件夹 = 一次报销单。每张发票一个文件（或一个 zip），文件夹里不要放无关文件。

3.2 召唤专家

1
进入专家中心左侧边栏「专家」→「我的专家」→ 点击「JG报销助理」卡片，开始对话
2
告诉它素材位置直接说，例如：
"扫描 /Users/xxx/Desktop/报销/8月差旅 文件夹，生成报销摘要"

3.3 两阶段流程

阶段做什么产出
阶段一：扫描确认 专家扫描文件夹，识别每张票据，生成报销摘要。黄色/红色标记的地方（如地点类型待确认）需要你人工核对修改 05-需确认-报销摘要.xlsx
阶段二：生成终稿 你确认摘要无误后，让专家「生成终稿」 09-终稿-*（OA 明细 / 交通费明细 / A4 PDF）
3
核对摘要打开 05-需确认-报销摘要.xlsx，重点核对：金额、日期、起止地方向（尤其高铁去/返程）、住宿开票日、补贴天数、黄色标记项
4
生成终稿对专家说：「摘要确认好了，生成终稿」→ 得到 OA 明细、交通费明细、A4 拼贴 PDF
5
提交报销A4 PDF 打印后贴到报销单，OA 明细填 OA 系统，完成提交

4更新

报销规则更新（无需任何操作）

报销规则/解析能力升级后，由管理员更新 GitHub 仓库即可。你什么都不用做——下次使用专家时，它会自动拉取最新版报销规则。

💡 不确定是否已用上新版？对话时让专家先跑一次，或问它「当前用的报销规则是哪天的版本」。

专家本身更新（极少发生）

只有当专家的对话指令、头像等自身内容变化时，才需要重新导入新版 zip：

1
拿到新版 zip由管理员分发新版 jg-reimburse-assistant.zip
2
重新导入覆盖与首次安装方式相同：专家中心「导入」选择新版 zip，同名覆盖即可
3
重启生效完全退出并重启 WorkBuddy
⚠️ 更新前如正在报销流程中，请先完成当前单据或删除中间产物（05/09 开头的文件），再重跑，避免新旧混用。

5常见问题（FAQ）

问题解决办法
导入后专家列表看不到完全退出并重启 WorkBuddy；确认 zip 解压后目录名是 jg-reimburse-assistant 且放在 my-experts/plugins/ 下
提示「无法连接 GitHub / 拉取失败」说明电脑访问不了 GitHub：检查网络（公司代理/VPN）、确认已安装 git；解决后重新对话即可，不影响已生成的报销文件
扫描后没有识别到某张票确认文件是 PDF/XML/OFD 且未损坏；试试单独新建文件夹只放这一张票重跑；或直接在摘要里手动补一行
酒店住宿发票显示 unknown / 识别不到属已知限制：部分住宿专票 PDF 无法自动识别。专家会读 PDF 人工确认「专票 / 金额 / 税额 / 开票日」并在摘要中补全，你核对金额即可
高铁到达时间空着 / 方向待确认专家会按规则查公开时刻表（12306）复核方向并补到达时间。摘要里「出发地/目的地」两列请重点核对，错了直接改后重新生成终稿
交通费明细里没有高铁正常：高铁发票直接进 A4 拼贴，交通费明细只列打车（市内交通）
金额和发票对不上摘要里金额都是「价税合计」（实际支付金额），专票会单独列税额；有疑问可以人工改摘要，改完再生成终稿即可
地点类型标了黄色「待确认」行程单里没有明确 POI 时无法自动判断类型，人工补一下即可
高铁方向识别反了先确认票面，摘要中手动纠正「起/止」地后重新生成终稿
生成 PDF 报错 / 缺字体重试一次；仍失败则联系管理员（报告报错信息），不要在本地乱改配置

6管理员维护（分发者专用）

以下内容供负责维护和分发的同事使用。

日常维护：只需维护 GitHub 仓库

  1. 报销 skill 的修复/更新由 Codex 维护，推送到 GitHub 仓库 yideng-xl/jg-work-plugin-codex
  2. 同事侧无需任何操作——专家每次执行自动拉取最新版
  3. skill 更新后不需要重新打包 zip 分发给同事
  4. 版本基线：2026-08-17 已用仓库最新 skill 完整跑通一单真实报销验证

只有以下情况才需要重新打包 zip

  1. 修改了专家本身的指令（agents/jg-reimburse-assistant.md）
  2. 更换了头像、改展示信息（plugin.json）
  3. 此时在 WorkBuddy 中对助手说：「重新打包专家」，再把新 zip 发给尚未安装的同事

检查当前安装的版本

专家目录下 .codebuddy-plugin/plugin.json 的 version 字段即为当前版本号。
