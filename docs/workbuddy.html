安装

导入 JG报销助理

首次使用时，下载专家包并在 WorkBuddy 桌面端导入。

  1. 1

    打开专家中心

    启动 WorkBuddy，进入左侧“专家”入口。

  2. 2

    导入专家包

    在专家中心或“我的专家”中找到“导入”，选择 jg-reimburse-assistant.zip。

  3. 3

    确认导入结果

    在“我的专家”中找到“JG报销助理”。

  4. 4

    重新启动

    如果没有显示，完全退出并重新打开 WorkBuddy。

找不到导入入口：手动安装

解压得到 jg-reimburse-assistant/ 文件夹，将整个文件夹复制到下面的目录，然后重启 WorkBuddy。

~/.workbuddy/plugins/marketplaces/my-experts/plugins/

报销规则自动更新

专家每次开始处理报销时，会从 GitHub 拉取最新规则。电脑需要安装 Git，并能够访问 GitHub。若拉取失败，检查网络后重试。

仅报销规则更新时，无需重新导入专家包；专家自身的指令或展示信息更新后，再下载新版包重新导入。正在处理的报销先完成并保留已有文件。

01

在 WorkBuddy 中发起报销

在“专家 → 我的专家”中打开“JG报销助理”，提供材料位置、报销类型和实际报销人。

差旅报销

帮我处理差旅报销，材料在这个文件夹：文件夹路径，报销人是实际报销人姓名。

其他报销

帮我处理其他报销，材料在这个文件夹：文件夹路径，报销人是实际报销人姓名。

02

检查并修改确认表

打开 05-需确认-报销摘要.xlsx，直接修改需要调整的内容。

  • 报销人、费用分类和票种正确。
  • 费用发生日期和金额正确。
  • 差旅行程的出发地、目的地正确。
  • 打车地点类型和打车原因正确。
  • 补贴天数和报销事由正确。
  • 标黄、标红内容已经处理。

修改完成后回复

摘要确认好了，可以生成终稿。

03

生成 09-终稿文件

专家 会重新读取你确认后的摘要，再生成本次报销需要的文件。

交通费明细仅在存在对应打车明细时生成。

其他报销

高铁票准备两份：一份粘贴，一份随报销单交财务。没有对应票种时，不生成空 PDF。

问答

常见问题

保留原始票据与已修改的摘要，针对具体问题核对。

导入后找不到专家

完全退出并重启 WorkBuddy。手动安装时，确认目录名为 jg-reimburse-assistant，且位于 my-experts/plugins/ 下。

提示无法连接 GitHub 或拉取失败

确认电脑已安装 Git，并能访问 GitHub。连接恢复后重新发起，不影响已有的报销文件。

漏识别发票或住宿专票信息不全

把具体文件名告诉专家，让它核对原始票据，补齐票种、金额、税额与开票日期，再合并进已有摘要。

高铁方向、到达时间或打车地点待确认

核对票面和原始行程。到达时间可按公开时刻表复核；起止方向、地点类型不确定时，在摘要中确认后再生成终稿。

交通费明细里没有高铁

交通费明细只列对应的打车明细。高铁发票进入 A4 发票打印文件。

金额与发票对不上

摘要金额使用价税合计，专票税额单列。核对原始发票后修改摘要，再生成终稿。

生成 PDF 报错或缺少字体

保留报错信息，重试仍失败时交给维护者排查。

维护者说明：规则更新与专家包更新

报销规则由 GitHub 仓库维护。规则更新后，专家在下次处理报销时拉取，无需重新分发专家包。

修改 agents/jg-reimburse-assistant.md、头像或展示信息后，需要重新打包专家，并更新下载文件。专家包版本可查看 .codebuddy-plugin/plugin.json 中的 version 字段。
